## The problem

When I go to a specific claimset, for instance: /as/1/sb-environments/2/edfi-tenants/2/claimsets/2
For both v2 and v3 we have a problem which is that, for a given resourceClaims item, if it does not have any actions associated, it will be excluded from the response from Admin Api.
This is /v2/claimSets/<claimset id> and /v3/claimSets/<claimset id>

## Starting point files

1. packages\fe\src\app\Pages\ClaimsetV2Plus\ClaimsetsPage.tsx
2. packages\fe\src\app\Pages\ClaimsetV2Plus\ClaimsetPage.tsx
3. packages\fe\src\app\api\queries\queries.v7.ts line 374
4. packages\api\src\teams\edfi-tenants\starting-blocks\v3\admin-api.v3.service.ts line 545

## The Solution

We need to include all the resourceClaims items, even those that do not have actions associated.

We have another endpoint in Admin Api that returns all the resourceClaims. Let me give you a section of a response when I call it:

[
  {
    "id": 1,
    "name": "types",
    "parentId": 0,
    "parentName": null,
    "children": [
      {
        "id": 12,
        "name": "schoolYearType",
        "parentId": 1,
        "parentName": "types",
        "children": [
        ]
      }
    ]
  }
]

We will need to somehow merge both responses to include those resourceClaims that are not part of the current response.
For those resourceClaims items that do not have actions associated, we can assume the columns: read, create, update, delete and readchanges will be Denied.
